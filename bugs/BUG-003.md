# BUG-003 — API aceita e-mails malformados

## Resumo

`POST /api/pedidos` aceita endereços com ponto duplo em posição inválida, apesar da regra exigir formato de e-mail válido. O navegador bloqueia `ana@dominio..com`, mas a API cria o pedido.

## Severidade

Média

## Prioridade

Média

## Ambiente

- URL: https://verzel-store.qa-test-verzel-store.workers.dev/
- Endpoint: `POST /api/pedidos`
- Navegador: Chromium integrado
- Data: 2026-10-06

## Passos para reproduzir

Enviar `POST /api/pedidos` com cliente válido, item `P005` quantidade 1 e um destes e-mails:

- `ana@dominio..com`
- `ana..silva@dominio.com`

## Resultado esperado

- HTTP `422`, código `DADOS_INVALIDOS`, campo `cliente.email`.

## Resultado atual

- Ambos os endereços foram aceitos com HTTP `201` e o pedido fictício foi confirmado.
- Na UI, o navegador identifica `ana@dominio..com` como formato inválido e bloqueia o envio.

## Impacto

Chamadas diretas à API contornam a validação de e-mail da interface e confirmam pedidos com endereço malformado.

## Status

Reproduzido; aguardando correção
